A layer you control between RAM and disk.

Files dropped into GhostLayer live in a RAM-backed staging layer — volatile, inspectable, and never written to disk until you commit them. Open a staged file in its associated editor and GhostLayer synchronizes your edits back into RAM. Opening for edit creates a temporary disk copy; the temporary is removed when the edit session closes normally. Wipe the layer and the uncommitted files are gone. No residual copies, no background sync, no cloud backup you did not authorize.

RAM-Backed Staging

Dropped files live in a RAM-backed layer. They are visible, sortable, and manageable inside the app. Opening a file for editing creates a temporary disk copy that is removed when the edit session closes normally.

Deliberate Commit

Choose which files to write to disk and where. GhostLayer commits exactly what you select, nothing more. Instant Wipe

One action clears the staging layer. Uncommitted files are removed from RAM. The layer is empty and ready for the next session. What was not committed was never written.

Stage → Select → Edit → Recover → Commit Safely

Five deliberate steps. No hidden actions between them.

01 / STAGE
Drop files into RAM

Drag and drop files into the GhostLayer window. They appear in the staging list with their names, sizes, and status. They exist in RAM — no disk writes occur at this stage. The layer is volatile by design.

02 / SELECT
Multi-select with keyboard

Select multiple files with checkboxes, Ctrl+A to select all, or Shift-click for range selection. Commit Selected or Discard Selected operate on the chosen subset only. Unselected files are unaffected.

03 / EDIT
Open in your editor

Open a staged file in its associated desktop application. When you save in the editor, GhostLayer synchronizes the changes back into the staged RAM copy and marks the file as modified. Opening for edit creates a temporary disk copy that is removed when the edit session closes normally.

04 / RECOVER
Recover from interruptions

If a destination changed after staging, GhostLayer blocks the commit and offers non-destructive recovery: Keep Staged, Show Destination, or Save Copy. Save Copy creates a new file only and never overwrites an existing filesystem object. Interrupted edit sessions leave recoverable temporaries — never auto-deleted.

05 / COMMIT
Write only what you choose

Commit the files you want to keep. The commit destination is derived from the staged file identity in the main process — a renderer-supplied destination cannot redirect the write. What was not committed was never written.

Conflict safety: GhostLayer's block-on-conflict guard is preserved. If a destination file changes on disk after staging, the commit is blocked and both versions are kept — the staged RAM copy and the changed disk file. There is no Overwrite or force-commit operation.

Local-first. User-controlled. No telemetry.

GhostLayer is built on a simple principle: your files stay on your machine, in your control, until you decide otherwise. No cloud account, no subscription, no telemetry, no background network activity.

No Cloud, No Account

GhostLayer does not require or request any cloud account. It does not sync, upload, or phone home. The application runs entirely locally.

No Telemetry

No analytics, no crash reporting to a remote server, no usage tracking. What happens in GhostLayer stays on your machine.

User-Owned Persistence

You decide what persists. Files in the RAM layer are volatile; files you commit are permanent. There is no middle ground and no surprise — the boundary is explicit and user-controlled.

What this is — and is not

  • Unsigned by Windows. The installer is not Microsoft publisher signed. Windows SmartScreen may show "Windows protected your PC" — choose More info → Run anyway.
  • Receipt-backed, not code-signed. The SHA-256 and Proof Foundry release receipts establish artifact custody — they do not establish Microsoft code signing, SmartScreen trust, or third-party security attestation.
  • What you verify is that the bytes you downloaded match the bytes Reality Gate inspected at build time. That is a custody claim, not a safety claim.
  • No auto-update channel. Updates are manual downloads with fresh checksums. No background update mechanism is included.
  • Local-only by design. No cloud sync, no account, no telemetry — which also means there is no remote dashboard and no remote wipe.
