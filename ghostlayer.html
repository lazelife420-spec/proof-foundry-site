The disk boundary

Know the boundary.

Opening a file for editing creates a temporary disk copy. It is removed when editing closes normally; interrupted edits can leave recoverable copies. RAM staging is not a promise that files never touch disk.

Stage → Select → Edit → Recover → Commit Safely

Five deliberate steps. No hidden actions between them.

01 / STAGE
Drop files into RAM

Drag and drop files into the GhostLayer window. They appear in the staging list with their names, sizes, and status. They exist in RAM — no disk writes occur at this stage. The layer is volatile by design.

02 / SELECT
Multi-select with keyboard

Select multiple files with checkboxes, Ctrl+A to select all, or Shift-click for range selection. Commit Selected or Discard Selected operate on the chosen subset only. Unselected files are unaffected.

03 / EDIT
Open in your editor

Open a staged file in its associated desktop application. When you save in the editor, GhostLayer synchronizes the changes back into the staged RAM copy and marks the file as modified. Opening for edit creates a temporary disk copy that is removed when the edit session closes normally.

04 / RECOVER
Recover from interruptions

If a destination changed after staging, GhostLayer blocks the commit and offers non-destructive recovery: Keep Staged, Show Destination, or Save Copy. Save Copy creates a new file only and never overwrites an existing filesystem object. Interrupted edit sessions leave recoverable temporaries — never auto-deleted.

05 / COMMIT
Write only what you choose

Commit the files you want to keep. The commit destination is derived from the staged file identity in the main process — a renderer-supplied destination cannot redirect the write. Uncommitted staging is volatile. Opening an editor creates a temporary disk copy; interrupted edits can leave recoverable copies.

Conflict safety: GhostLayer's block-on-conflict guard is preserved. If a destination file changes on disk after staging, the commit is blocked and both versions are kept — the staged RAM copy and the changed disk file. There is no Overwrite or force-commit operation.

Privacy & Data Flow

RAM-first staging. Disk-backed editor copies.

Evidence-backed behavior for GhostLayer Windows v0.4.0.

01

RAM staging & temp disk files

Primary file staging is held in volatile RAM (lost on app close). Launching external text editors creates temporary working files in %TEMP%\GhostLayer\, which are purged on commit or discard.

02

Network boundary

Zero network capabilities or internet connections exist in audited GhostLayer source. All staging, conflict resolution, and file commits occur locally on your machine.

03

Telemetry & safety

Zero background telemetry or analytics tracking. Interrupted edit sessions retain recoverable temporary disk copies so no working edits are silently lost.
