Windows Guidance

Windows security warnings & SmartScreen

Unsigned or low-reputation software executables may trigger Windows SmartScreen prompts ("Windows protected your PC / Unknown Publisher") on launch.

  • Verify the artifact identity by checking its SHA-256 checksum on your computer prior to running.
  • A matching SHA-256 checksum confirms that your local file is byte-for-byte identical to the published build artifact.
  • A matching digest does not itself prove safety, publisher identity, or Microsoft SmartScreen reputation.
  • The user must review the SHA-256 match and decide whether to proceed based on local trust requirements.

Note: Proof Foundry software binaries do not instruct users to bypass OS security controls unconditionally. See The Proof Standard ↗ for our complete verification doctrine.

Android Guidance

Android installation & APK verification

Installing Android APK packages directly (such as ForgeCast Weather or mobile companion apps) requires granting your web browser or file manager permission to install unknown apps.

  • Before installing an APK, verify the SHA-256 digest on a desktop device using PowerShell (Get-FileHash .\<apk-filename> -Algorithm SHA256) or terminal tools.
  • Phone-native verification guidance is being prepared on the support hub.
  • Seamless in-place app updates require signing continuity across versions. If an app update fails to install over an existing version, verify signing compatibility details on the product page.

Verification Standard

Checksums & artifact identity

SHA-256 match = byte-identity verification against the published digest.

A matching SHA-256 confirms that the file you have is byte-for-byte identical to the artifact identified by the published digest.

The 8-Field Checksum Identity Schema

Every primary download checksum block presents the following identity context:

  1. Product: The canonical software product name.
  2. Version: Exact semantic version string (e.g. v1.1.0).
  3. Release / Channel state: Public release, release candidate, or pilot.
  4. Artifact filename: The exact expected file name.
  5. SHA-256: The 64-character hex cryptographic hash digest.
  6. Match scope: Confirms local file byte-identity matches the published digest.
  7. Signing / Publisher state: Explains code signature or unsigned status.
  8. Verification method: Platform command (e.g., Get-FileHash .\file.zip -Algorithm SHA256).

Distinction: SHA-256 digest matching verifies file integrity against the published manifest. It is distinct from Authenticode code signing, publisher identity verification, SmartScreen / Play Protect reputation, or third-party security audits. SHA-256 alone is not used to claim an artifact is signed or malware-free.
