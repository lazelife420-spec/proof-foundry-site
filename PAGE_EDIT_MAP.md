# Page edit map

Every visible section on every public route, mapped to the one file you edit and the stylesheet that owns its look. Line numbers are for the candidate worktree (`codex/pf-modular-html-r1`). "Generated" means the builder fills it in from product modules or release truth: edit the source named, never the output.

**Stylesheet order (builder-enforced, `scripts/build-site.ps1` `Process-Template`):** page sheets → `foundry-world.css` → `pf-site-ledger.css` → `pf-foundry-system.css` (last, wins ties; Home skips the first two injected sheets). Full ownership rules: `CSS_OWNERSHIP_AND_MATERIAL_CONTRACT.md`.

**Shared on every route:** header = `partials/header.html` (nav links and CTA generated from `site-manifest.json` nav; brand mark swapped for `brand/PF_MARK_G_HEADER.webp` at build) · footer = `partials/footer.html` (product list generated) · style owner = `pf-foundry-system.css`. `partials/footer-compact.html` is **dormant**: `@include compact-footer` emits the standard footer.

## Known quirks (left in place, documented)

- Unstyled bespoke class families (`gl-*`, `lo-*`, `ps-*`, most `rg-*`) render through generic `.evidence-section` rules in `studio.css`. Styling them means adding scoped rules in `product-page.css`.
- Classes emitted but styled nowhere: `storefront`, `support-studio`, `roadmap-unavailable`, `standard-principles-section`, `standard-boundary-section`, `standard-routes-section`, `limit-note`.
- `module.json` `order` (product page order) and `homepage.order` (home placement) are separate fields.
