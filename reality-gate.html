The Platform as Five Concrete Systems

Reality Gate is organized around five distinct operational capability systems — not vague marketing features.

01 / WORKSPACE

Isolated Workspace

Executes CI steps and builds inside isolated local clones (git clone --local --no-hardlinks). Authoritative user repositories remain 100% untouched and unmutated.

02 / RUNROOM

Runroom Control

Provides controlled execution, step queueing, real-time log streaming, process cancellation, and toolchain command whitelisting (Node, Python, Git, Make).

03 / EVIDENCE

Evidence Capture

Records SHA-256 hashes of all inputs, environment variables, step outputs, and final artifacts, creating an immutable inspection trace for every run.

04 / RECEIPTS

Signed Receipts

Signs execution outcomes with local machine ECDSA P-256 keys. Emits self-contained Proof Passport JSON receipts that verify provenance independently.

05 / RECOVERY

Recovery Vault & Ledger

Creates verified Git bundles, tests restore paths in advance, and persists run records into a local Proof Ledger — ensuring local continuity during provider outages.

Execution Architecture & Evidence Flow

Every node in this architecture corresponds to an implemented capability in the local product runtime.

When a workflow executes through Reality Gate, the platform creates a temporary local clone, executes whitelisted commands inside that sandbox, collects execution logs and artifact checksums, and signs the outcome before persisting the receipt to the local Proof Ledger.

  • Zero Authority Mutation: User source repositories and remotes are never edited or rewritten.
  • Local Cryptographic Keys: ECDSA P-256 keys are generated and held locally in AppData.
  • Offline Execution Safety: Drills remove remote network credentials to verify true local operation.

Explicit Developer Pilot Limits & Plain-Language Boundaries

  • Windows Only: Supported on Windows 10/11 x64. No macOS or Linux packages are available.
  • Unsigned Package: Windows SmartScreen may show "Windows protected your PC" on first launch — choose More info → Run anyway after verifying SHA-256.
  • Manual Update Model: No auto-updater; updates require fresh ZIP downloads and SHA-256 verification.
  • Local-First Scope: Local data is stored in AppData. No cloud accounts, cloud sync, or remote dashboards exist.
  • Plain-Language Boundaries: Receipts prove what was executed, hashed, and signed. They are not legal attestations, security certifications, or guarantees against third-party provider outages.
