## Finding: three files named `.png` contain JPEG data

| File | Extension | Actual container |
|---|---|---|
| `assets/lights-out/companion-active.png` | `.png` | JPEG |
| `assets/lights-out/companion-reconnected.png` | `.png` | JPEG |
| `assets/lights-out/companion-snoozed.png` | `.png` | JPEG |

Provenance and scope:

- These are pre-existing, git-tracked files. `git status` reports them unmodified by this candidate.
- They were committed in `308d2f1` (2026-09-07, "restore deployed site source, byte-equal to live"),
  so the same mislabelling is present on the live site today.
- They are referenced only by `public/lights-out/index.html`. The homepage does not request them.

Consequence: a strict static host will serve these with `Content-Type: image/png` while the body is
JPEG. Browsers sniff the container and render them, so there is no visible breakage, which is why it
went unnoticed. It is still a mislabelled asset.

Not fixed here, deliberately. Correcting it means either re-encoding the three images to real PNG or
renaming them to `.jpg` and updating the Lights Out page references. Both touch product assets on a
page outside this homepage candidate, so it needs its own decision and its own change. Raised for the
owner rather than folded silently into this diff.
